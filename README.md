# Snake AI Lab 🐍

一個用來**觀察演算法行為**的貪吃蛇實驗場（pygame）。

老實說，這個專案沒有預設的研究目標。它的玩法是：把環境機制做出來
（體力、地形、道具、雙層棋盤，全部可開關）、把各路演算法接上統一介面、
批量跑幾千局，然後看數據裡浮出什麼。與其說在回答問題，不如說在收集
「環境規則一改，演算法行為跟著怎麼變」的標本。

目前為止撈到的兩個比較有意思的：

- 古典必勝解法（漢米爾頓迴路）加入「體力」機制後必然餓死 ——
  它的安全保證建立在「等待免費」的世界裡，而體力本質上是一條
  「平均 N 步內必須進食」的配速線。
- 貪婪流的天花板其實是**空間破碎**（蛇身把自由空間切成碎片）——
  加一片純逃生用的地下層，分數立刻 +38%。

## 執行

```bash
python3 -m venv .venv
.venv/bin/pip install pygame-ce
.venv/bin/python snake_game.py
```

macOS 也可以直接雙擊 `啟動貪吃蛇.command`（會自動建環境）。

外部套件版演算法（`BFS·庫`／`DIJ·庫`／`A*·庫`）需要另外裝：
`.venv/bin/pip install networkx pathfinding`（沒裝會自動略過，遊戲照常能玩）。

📽 不想跑就先看 [演示影片](演示.mp4)：自動模式跑分 → 下拉選單切換演算法 → 暫停。

### 批量模式（無視窗跑整局、定量對比演算法）

```bash
.venv/bin/python batch_run.py                    # 名冊裡全部演算法各跑 30 局
.venv/bin/python batch_run.py --games 1000 --algos BFS,DIJ庫
.venv/bin/python batch_run.py --jobs 1           # 除錯用：關掉並行
```

- multiprocessing 並行（預設 CPU 核數-1）；每完成一局立刻寫入
  `批量結果.jsonl` 並印進度，背景跑也能隨時看進到哪
- 第 g 局固定用種子 `seed+g`：每個演算法拿到**同一批地圖**，同題作答、
  結果完全可重現。種子只管地圖——實驗參數永遠走顯式欄位，不塞進種子
- 想快 ~2.4 倍：裝 [PyPy](https://pypy.org/) 建第二套環境跑批量
  （`brew install pypy3 && pypy3 -m venv .venv-pypy &&
  .venv-pypy/bin/pip install networkx pathfinding`），
  與 `.venv` 並存互不干擾；兩個直譯器同種子結果逐位一致

## 演算法名冊

| | 策略 | 特性 |
|---|---|---|
| **BFS** | 最短路＋吃完追得到尾巴才走＋跟尾巴等機會 | 貪婪流對照組，進食效率最高 |
| **DIJ** | 按體力代價找最省的路＋恐慌賭路＋藍蘋果減重 | 規則更多，不一定更強 —— 手寫規則的天花板展示 |
| **A\*** | 同 DIJ 策略層，原語換 A*（曼哈頓啟發式） | 分數與 DIJ 統計等價，決策快 2.8 倍 —— 工程最優解 |
| **HAM** | 漢米爾頓迴路＋編號捷徑（perturbed Hamiltonian） | 數學上不可能撞到自己；但在體力機制下必然餓死 |
| **嫁接** | 前期 DIJ 衝分，蛇長 80 切換 HAM 保命 | 被 1000 局數據推翻的實驗品（−951 分），保留作反面教材 |
| **BFS·庫 / DIJ·庫 / A\*·庫** | 同上述策略層，尋路原語換外部套件（python-pathfinding / networkx） | 手寫 vs 成熟庫的活體對照（`compare_pathfind.py` 是離線差分驗證） |

統一介面 `fn(game) -> (方向, 模式標籤)`，新演算法加進
`algorithms/__init__.py` 的 `AUTO_ALGOS` 就會出現在遊戲與批量裡。
畫面上會即時顯示 AI 當下的決策模式，所有行為同步寫入
`行為記錄.txt`（人讀）與 `行為記錄.jsonl`（程式分析）。

## 雙層棋盤與電梯（`ENABLE_LAYERS`）

貪婪流在單層的真正天花板是**空間破碎**：蛇身是平面上的一條曲線，
曲線就能把自由空間切成兩半。對策——加一片棋盤：

- 兩片 28×22 疊起來，**四個角是電梯**：踏上角格就到另一層的同位置角格
  （出電梯若直行會撞牆，自動沿牆轉向）
- **物品只刷在上層**；下層不生成任何東西，是純逃生／繞行空間 ——
  食物經濟完全不變，所有增益乾淨地歸因於拓樸逃生通道
- 演算法不需要「學會搭電梯」：`pathfind.neighbors()` 把電梯建成一條
  跨層邊，BFS/DIJ/A* 的搜索邏輯零修改自動通行
- 雙層名冊：手寫與庫版共 6 個（庫版統一走 networkx 圖；HAM／嫁接
  依賴單層迴圈編號，暫不支援）

## 環境機制（都在 `environment/config.py` 可調）

- **體力**：每步 -1，歸零餓死；吃蘋果回補。`ENERGY_RED` 就是配速線 ——
  調高它，古典流派就能活；調低它，連貪婪流都窒息
- **紅蘋果** +10分/長1節/體力+30、**金蘋果** +50分/長3節（限時）、
  **藍蘋果** -20分/減3節（減重與分數的權衡，限時）
- **碎石地**（體力消耗×3）、**石頭**（撞死）、**傳送門**、**雙層棋盤** ——
  各有開關；石頭／碎石地／傳送門預設關（乾淨棋盤），雙層預設開

## 專案結構

```
snake_game.py       入口＋介面層（畫面、音效、輸入、行為記錄）
batch_run.py        批量模式（無視窗跑整局，multiprocessing 並行）
compare_pathfind.py 手寫尋路 vs 外部庫：差分驗證＋效能對比
收斂推導.html        臨界局數 k* 的完整推導（統計筆記，瀏覽器直接開）
簡報.html            專案介紹簡報（方向鍵翻頁）
environment/        環境機制
  config.py         所有參數與開關
  game.py           規則本體（無視窗可跑，批量模擬／RL 都靠它）
algorithms/         演算法（介面統一：fn(game) -> (方向, 模式標籤)）
  pathfind.py       手寫 BFS / Dijkstra / A* ／ neighbors（雙層鄰接）／ 前向模擬
  pathfind_lib.py   外部庫同介面原語（python-pathfinding / networkx）
  greedy_bfs.py     greedy_dij.py   hamilton.py   graft.py
```

## 實驗結論（各 1000 局，種子配對，乾淨棋盤）

**單層**：

| 流派 | 平均分（95% CI ±37~46） | 結局 |
|---|---|---|
| 貪婪流（DIJ 2176 ≥ A* 2160 > BFS 1953） | 1950~2180 一帶 | 死亡長度中位 ~150-180（26% 填充），六成餓死、四成自困 |
| 嫁接（DIJ→80→HAM） | 1225 | 交接期安全保證失效＋交棒點超出 HAM 生存邊界，**被推翻** |
| 古典流（HAM） | 446 | 100% 餓死 —— 前跳約束幾何下界 ~32 步/顆 > 配速線 30 |

**手寫 vs 庫**：路徑代價差分驗證全數一致；行為上手寫 A*、庫版 A*、手寫
DIJ 三者統計等價，唯 networkx Dijkstra 的平局選擇系統性偏差（−108~−124 分）
—— **原語等價 ≠ 策略行為等價**。

**雙層紅利**：BFS +739、DIJ +844、A* +824（+38~39%，t≈26~28）。
死亡長度中位推到 ~235-240（39% 生產空間填充），但**死因比例幾乎不變** ——
逃生層拉長跑道，不改變死亡的形狀；經濟牆（配速線）依然收走六~七成。

**方法論**：批量對比的收斂用累積平均圖診斷，SE = σ/√n；要把平均釘到
±ε（95% 信心）需要 k* = (1.96·σ/ε)² 局。環境的參數決定哪個流派勝出 ——
這正是這個實驗場想展示的事。
